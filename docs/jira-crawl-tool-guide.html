JIRA TTM Crawl Tool — Phiên bản v14

Công cụ chuyên biệt trích xuất dữ liệu phân cấp 3 tầng Epic → Story → Subtask từ hệ thống Jira Data Center 8.2 (MBBank), tối ưu hóa tải ngặt nghèo (Rate Limit ~5 req/phút), chuẩn hóa Flat CSV và tự động nạp dữ liệu trực tiếp vào hệ thống giám sát thời gian ra mắt thị trường (TTM Monitor / ttm-tool).

Phiên bản: v14 (RCA Update)
Hệ điều hành: Windows 10/11 / Server
Môi trường: Python 3.9+
Đích nạp: ttm-tool Ingestion API

1. Tổng quan & Kiến trúc Hệ thống

Trong quy trình vận hành và đo lường chỉ số Time-to-Market (TTM-CNTT & TTM-E2E) tại Ngân hàng, dữ liệu nguồn phân tán tại Jira Data Center với số lượng Issue rất lớn. Tuy nhiên, Jira Data Center áp dụng chính sách giới hạn tần suất gọi API (Rate Limit) rất ngặt (~5 request/phút/user). Jira Crawl Tool đóng vai trò là bộ tiền xử lý (Ingestion ETL Engine) thực thi độc lập tại máy trạm lập lịch, đảm nhiệm thu thập, gom cụm, lọc rác và đẩy dữ liệu sạch về ttm-tool.

+--------------------------------------------------------------------------------------------------+ | JIRA DATA CENTER 8.2 | | - Rate Limit: Limit=30, FillRate=5, Interval=60 (~1 req / 12s) | | - Endpoint: POST /rest/api/2/search & GET /rest/api/2/field | +------------------------------------------------┬-------------------------------------------------+ | (Gom lô JQL: "Epic Link" in, parent in) v +--------------------------------------------------------------------------------------------------+ | JIRA CRAWL TOOL (Python Engine) | | - JiraClient: Điều tốc Token Bucket (tránh 429) & Tự động dò Field Metadata | | - RunControl: Lắng nghe phím Windows (P: Tạm dừng, S: Chạy tiếp, P x 2: Lưu phiên gzip) | | - Logic gom cụm: Cắt tỉa Epic đã đóng, lọc Subtask Done qua Cache, gom lô parent | | - Build Flat CSV: Một dòng một issue, lặp thông tin cha, mặt nạ bảo mật (***) | +------------------------------------------------┬-------------------------------------------------+ | HTTP POST (Multipart/Form-Data, Bearer Auth) v +--------------------------------------------------------------------------------------------------+ | TTM-TOOL | | - API Route: POST /api/data-source/import/auto (Xác thực IMPORT_API_TOKEN) | | - Adapter: parsePyJiraApi() -> chuẩn hóa RawJiraIssue -> Database Ingestion | | - Scoring Engine: Chấm điểm vi phạm TTM-CNTT, TTM-E2E, phân rã Phase Alert | +--------------------------------------------------------------------------------------------------+
Cấu trúc Phân cấp (Hierarchy) 3 Tầng
  • Level 1 (Epic): Nguồn chính của sáng kiến TTM. Chứa các mốc ngày (Start, R4G, Due Date, Phê duyệt ý tưởng, Phân loại yêu cầu, Đơn vị yêu cầu, Đánh giá nguyên nhân RCA).
  • Level 2 (Story): Các yêu cầu chức năng bên dưới Epic, liên kết thông qua trường Epic Link.
  • Level 3 (Subtask): Các công việc kỹ thuật chi tiết. Hỗ trợ 2 kiểu quan hệ: Subtask trực thuộc Story (parent = Story) và Subtask trực thuộc thẳng Epic (parent = Epic).
Cơ chế xuất dữ liệu CSV Flat Format
  • Nguyên tắc One-row-per-issue: Mỗi dòng trong file CSV đại diện cho một issue thực tế (cột hierarchy_level = EPIC | STORY | SUBTASK).
  • Kế thừa thông tin cha: Dòng Story và Subtask tự động sao chép lại epic_key, epic_name để đảm bảo mỗi dòng dữ liệu đều độc lập và tự trọn vẹn.
  • Bảo mật Summary: Cơ chế epic_summary_marking tự động mã hóa giữa tên issue bằng chuỗi ***, giữ lại phần đầu và đuôi để kiểm tra tính duy nhất.

2. Các Tính năng Cốt lõi & Cơ chế Chịu lỗi

Điều tốc Token Bucket v13.4

Tự động giải mã các header X-RateLimit-* từ Jira. Duy trì một "thùng token" trên máy khách, tự giãn thời gian giữa các request để không bao giờ bị kích hoạt lỗi 429 Too Many Requests.

Tạm dừng & Tiếp tục v13.5

Bấm P để tạm dừng an toàn sau request hiện tại; bấm S để chạy tiếp. Bấm P lần 2 hoặc Ctrl+C: lưu trạng thái vào output/_resume/session.json.gz để tắt máy và chạy tiếp hôm sau.

Cache Subtask Done v11

Ghi nhận các Subtask đã xong vào group_*_subtask_status.json. Các lần crawl sau tự động gắn thêm JQL AND key not in (...) để không tải lại các task cũ.

Chịu lỗi mạng, Proxy 503 & Tự động Đẩy bù (Re-push Queue) v13.3

Trong môi trường mạng nội bộ doanh nghiệp qua Corporate Proxy, lỗi ProxyError: 503 Service Unavailable tại bước tạo đường hầm kết nối thường xuyên xảy ra. Công cụ được trang bị cơ chế tự phục hồi:

  • Retry với Linear Backoff: Tự động thử lại khi gặp lỗi kết nối với thời gian chờ tăng tuyến tính (5s, 10s, 15s...).
  • Hàng đợi đẩy bù (output/pending_import.json): Nếu hết số lần retry mà API vẫn không nhận, file CSV sinh ra và cache Subtask tương ứng được lưu vào hàng đợi. Ở lần chạy kế tiếp, tool sẽ tự động đẩy bù các file nợ trước khi bắt đầu crawl dữ liệu mới.
  • Lệnh đẩy thủ công: Có thể gọi lệnh run_ttm_crawl.bat --repush để đẩy lại toàn bộ các file CSV còn tồn đọng mà không cần query lại Jira.

3. Hướng dẫn Cấu hình Công cụ (Configuration Guide)

Hệ thống phân tách toàn bộ thông số thành 2 tập tin cấu hình JSON riêng biệt: jira_ttm_runtime_config.json (dành cho người vận hành) và jira_ttm_fields_config.json (cấu hình kỹ thuật của hệ thống).

Nguyên tắc phân tách cấu hình
Người vận hành chỉ cần chỉnh sửa file jira_ttm_runtime_config.json một lần khi thiết lập môi trường cá nhân hoặc khi cần thay đổi danh sách Project Key/Nhóm dự án. File jira_ttm_fields_config.json chỉ chỉnh sửa khi có thay đổi về quy tắc nghiệp vụ, mapping cột hoặc bổ sung trường mới.

Tập tin này kiểm soát tài khoản, token kết nối, danh sách nhóm dự án và các hạn mức dữ liệu.

3.3. Các Kịch bản Vận hành & Cấu hình Thực tế

Kịch bản 1: Bổ sung Dự án mới vào Nhóm có sẵn Thường dùng

Mở file jira_ttm_runtime_config.json, tìm đến nhóm cần thêm (vd: NhomA) trong mục epic_scope.project_groups và bổ sung Project Key vào mảng project_keys:

{
  "group_name": "NhomA",
  "project_keys": [
    "WM", "HCM", "BPMCN", "SSM1", "CNSPDT", "SMEDS", "ON", "MO", "SBU",
    "NEWPROJ"  // <-- Thêm Project Key mới tại đây
  ],
  "max_total_issues": 8000,
  "max_total_issues_project": 700,
  "enabled": "on"
}
Kịch bản 2: Cấu hình chạy tự động định kỳ (Task Scheduler / Unattended) Tự động hóa

Để công cụ chạy ngầm không dừng chờ người bấm phím xác nhận trên màn hình CMD:

  1. Trong jira_ttm_runtime_config.json, đặt "interactive_group_selection": { "enabled": "off" }.
  2. Đảm bảo các group cần chạy có "enabled": "on", các group tạm ngưng đặt "enabled": "off".
  3. Đảm bảo "on_failure": "continue" trong mục import_api để nếu 1 group lỗi thì các group khác vẫn được crawl tiếp tục.
  4. Thiết lập Windows Task Scheduler gọi file run_ttm_crawl.bat với quyền thực thi phù hợp.
Kịch bản 3: Chỉ Crawl xuất file CSV nội bộ, KHÔNG đẩy lên Server TTM Kiểm thử

Trong jira_ttm_runtime_config.json, sửa công tắc sau:

"POST_file_API": "off"

File CSV vẫn được tạo đầy đủ trong thư mục output/Du_an_*.csv với nội dung chuẩn hóa, nhưng hoàn toàn không gửi request HTTP nào tới server ttm-tool.

4. Chi tiết Bản cập nhật v14 — Bổ sung các trường RCA & Previous Status

Bản nâng cấp v14 bổ sung trường Previous Status cùng 9 trường dữ liệu phân tích nguyên nhân gốc rễ (Root Cause Analysis - RCA) dành riêng cho cấp độ Epic, phục vụ đánh giá khâu gây chậm tiến độ hoặc fail cam kết TTM.

STT Tên trường trên Jira (Logical Field) Tên cột xuất ra CSV (CSV Column) Kiểu dữ liệu Diễn giải & Quy chuẩn mapping
0 Previous Status epic_previous_status Status String Trạng thái trước đó của Epic (phục vụ theo dõi luồng chuyển trạng thái, rework, rollback).
1 Khâu BA epic_khau_ba Select Option Ghi nhận lý do chậm/fail thuộc khâu Phân tích nghiệp vụ (BA).
2 Khâu CO epic_khau_co Select Option Ghi nhận lý do chậm/fail thuộc khâu Vận hành thay đổi / Change Coordinator.
3 Khâu Dev epic_khau_dev Select Option Ghi nhận lý do chậm/fail thuộc khâu Phát triển phần mềm (Lập trình, review).
4 Khâu PM/SM epic_khau_pm_sm Select Option Ghi nhận lý do chậm/fail thuộc khâu Quản trị dự án / Scrum Master.
5 Khâu PO epic_khau_po Select Option Ghi nhận lý do chậm/fail từ phía Product Owner (chốt yêu cầu, tài liệu).
6 Khâu Pentest epic_khau_pentest Select Option Ghi nhận lý do chậm/fail do đánh giá bảo mật / an toàn thông tin kéo dài.
7 Khâu SA epic_khau_sa Select Option Ghi nhận lý do chậm/fail thuộc khâu Kiến trúc giải pháp (System Architecture).
8 Khâu SIT/UAT epic_khau_sit_uat Select Option Ghi nhận lý do chậm/fail thuộc khâu Kiểm thử tích hợp hệ thống hoặc nghiệm thu.
9 Khi chọn lý do khác, note rõ chi tiết thông tin lý do tại đây epic_note_ly_do_khac Textarea Văn bản giải trình chi tiết tự do. Hỗ trợ đầy đủ văn bản nhiều dòng (multi-line text) có xuống dòng.
Cải tiến đặc biệt trong Logic phân giải trường v14 Fuzzy Aliases
  • Xử lý sai lệch chính tả tự động: Do trên hệ thống Jira của MBBank trường số 9 có thể được đặt tên là "Khi chọn lí do khác..." (chữ "lí" ngắn) hoặc "Khi chọn lý do khác..." (chữ "lý" dài), hàm resolve_configured_fields() trong jira_ttm_export.py đã được tích hợp từ điển biệt danh (aliases) đa chiều, tự động nhận diện đúng custom field ID bất kể chính tả của instance.
  • Bao đóng an toàn nội dung nhiều dòng (RFC 4180): Khi xuất ra CSV, các nội dung có dấu xuống dòng \n trong trường lý do chi tiết được bọc chuẩn xác trong cặp ngoặc kép "...", đảm bảo khi bộ phân giải csv-parser.ts của ttm-tool đọc vào sẽ không bị nhảy dòng sai lệch.

5. Cẩm nang Vận hành, Phím tắt & Xử lý Sự cố

Bảng điều khiển Phím tắt trực tiếp trên Windows CMD Tương tác thời gian thực
Phím bấm Hành động của Tool Thời điểm áp dụng & Ghi chú
P Tạm dừng an toàn (Pause) Bấm khi tool đang chạy. Tool sẽ hoàn thành nốt HTTP request hiện tại rồi đứng chờ, không gửi thêm request nào lên Jira.
S Tiếp tục chạy (Continue) Bấm khi tool đang ở trạng thái Tạm dừng để tiếp tục crawl bình thường.
P (lần 2) Lưu tiến trình & Thoát an toàn Bấm khi đang tạm dừng: Lưu toàn bộ trạng thái vào output/_resume/session.json.gz rồi đóng cửa sổ CMD. Lần sau mở lại có thể chạy tiếp.
Ctrl + C Ngắt khẩn cấp & Tự động lưu Tool tự bắt tín hiệu ngắt, thực hiện lưu savepoint lô hiện tại vào file session trước khi thoát.
Xử lý Sự cố Thường gặp (Troubleshooting) Cần biết
  • Lỗi: "Mot cua so TTM Crawl khac dang chay (xem file output/_resume/run.lock)":
    Nguyên nhân: Có một cửa sổ crawl khác đang chạy song song, hoặc lần chạy trước bị crash bất thường khiến file khóa chưa kịp xóa.
    Khắc phục: Kiểm tra xem có cửa sổ CMD nào đang chạy không. Nếu không còn, xóa file output/_resume/run.lock rồi khởi động lại.
  • Lỗi: "ProxyError: Tunnel connection failed: 503 Service Unavailable":
    Nguyên nhân: Proxy mạng của ngân hàng chập chờn khi mở kết nối ra ngoài.
    Khắc phục: Tool đã tự động retry tối đa số lần cấu hình. Nếu vẫn lỗi, tool sẽ tự động ghi CSV vào hàng đợi đẩy bù. Bạn có thể đợi mạng ổn định rồi chạy: 
    run_ttm_crawl.bat --repush
  • Thông báo: "Saved session found. Y = continue, N = discard, C = close":
    Khắc phục: Nhấn Y để tiếp tục nốt phần dở của lần chạy trước (tiết kiệm tối đa thời gian query lại); nhấn N nếu bạn muốn bỏ phiên dở và crawl mới hoàn toàn từ đầu.
